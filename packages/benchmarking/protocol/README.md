# `@jinn-network/benchmarking-protocol`

Sealed, TEP-free record families for evidence-native benchmarking. The
package defines batch capture, Benchmark v2, Analysis Manifest, Evidence
Cohort, Matrix v2, Report payload v2, and optional commissioning-link records.

It does not discover evidence, run a benchmark, select a backend, assemble a
Matrix, sign a Report, or decide consumer trust.

## Pinned fixtures

`fixtures/` holds exact-byte golden records, one directory per record kind, in the same shape
`packages/benchmarking/records` uses: `valid.json` carries the canonical bytes and `valid.sha256`
carries the pinned digest. `fixtures/manifest.sha256.json` is the repo-wide drift guard
(`.github/scripts/fixture-manifest.mjs`).

The fixtures are read only by this package's own test suite -- they are not published, and the
readers live in `src/fixtures.test.ts` because production sources here import no node builtin.
`packages/benchmarking/evidence/fixtures/golden-lifecycle/digests.json` pins the same way, for the
tier-2 artifact digests that package's golden lifecycle test produces.

Regenerate the per-kind fixtures after changing `src/golden-documents.ts`:

```bash
yarn generate:fixtures
```

The golden-lifecycle digests are regenerated by running that test and copying the values vitest
prints in the diff.

Published fixtures are append-only and never edited in place
(`.github/scripts/fixture-immutability.mjs`): a byte that must change is superseded by a new
fixture plus a dated erratum in the manifest's `errata` array.
