# Protocol Vocabulary Audit — Names Before the Re-Seal

- **Version:** 1.0
- **Date:** 2026-08-04
- **Status:** **Ruled** — all dispositions decided by the operator in-session (Ritsu,
  2026-08-04); recorded in DR-2026-08-04
  ([`log/decisions/2026-08-04-spec-origin-and-vocabulary.md`](../../../log/decisions/2026-08-04-spec-origin-and-vocabulary.md));
  rulings inlined below at each question
- **Shape:** `design`
- **Scope:** the complete `https://jinn.network/…` identifier vocabulary — every term and
  namespace convention that will be sealed under the new origin — audited against external
  standards from primary sources, plus the migration constraints the census uncovered
- **Out of scope:** the migration mechanics (planned after the DR); product/UI copy;
  GLOSSARY.md economic terms
- **Context:** the operator ratified (2026-08-04, in-session): a dedicated identifier origin
  `spec.jinn.network` (option C); **one origin for all protocol URIs**, names and locators
  alike; and this audit before the one-time pre-publication re-seal, on the standard that the
  immutability law binds *published* identifiers and none of these has ever been published.
  This is the last moment renaming is lawful and cheap.

## 1. Method

Three research lanes, run 2026-08-04: (a) a full repository census of the URI space; (b) the
provenance/attestation/verification vocabulary against in-toto, SLSA, W3C VC 2.0, PROV,
**RFC 9334 (RATS)**, DSSE, OpenTelemetry, RO-Crate, and audit practice (ISA 500); (c) the
work/market vocabulary against Kubernetes, Tekton, Temporal, CI systems, Celery,
StandardBounties, and OLAS Mech, plus namespace/versioning conventions against atproto,
CloudEvents, SLSA/in-toto TypeURIs, W3C "Cool URIs", w3id/purl, schema.org, and the XML
namespace post-mortem. Primary sources cited in the lane reports; the adopt/reject reasoning
below preserves their strongest arguments both ways.

## 2. Census summary

**282 distinct URIs** in the active tree (271 in shipped code). Only **5 are registered
resolvable** (the catalog's `resolvableIdentifiers`); 277 are pure names. ~35 first-segment
namespaces; the load-bearing ones: `records/` (70), `task-profiles/` (24), `profiles/` (22),
`agents/` (19), `software/` (12), `terms/`, `schemes/`, `formats/`, `attestations/`,
`trust/`, `record-discovery/`, `protocols/`.

**Five version conventions are live simultaneously:** `/1.0` (dominant; *enforced* for
record kinds by `discovery/protocol/src/grammar.ts`), `/v1` (*enforced* for trace formats by
`trace-decode/src/formats.ts`; used by `attestations/`, `trust/`), bare `/1` (five
production `records/…` URIs in task-supply — **violating the record-kind grammar their own
layer enforces**), `v1` as a directory with `/1/` in the `$id`, and unversioned.
`records/result-evaluation/1.0` and `attestations/result-evaluation/v1` name the same
concept under two conventions.

## 3. Hard constraints on the migration (census findings)

1. **`TEP_ATTEMPT_NAMESPACE` is frozen entropy.** The v5 UUID namespace
   (`task-execution/protocol/src/identifiers.ts:9-13`) is derived from the literal string
   `"jinn.network/task-execution/attempt"`. Every Attempt URI on the network descends from
   it. **Disposition: keep the namespace UUID unchanged.** It is an opaque seed; the source
   string is sealed history (the `jinn.trajectory.v1` precedent), not a living reference to
   the origin. Regenerating it would invalidate every existing Attempt URI for zero gain.
2. **Pinned wire identifiers stay pinned:** `jinn.trajectory.v1`, DSSE payload types,
   deployed contract vocabulary (`ClaimRegistry.sol`). Prose migrates; sealed/deployed
   identifiers do not.
3. **A false, untested invariant (live bug, filed separately):**
   `marketplace/pipeline/src/facts-mapper-kinds.ts` declares
   `records/task-execution/submission/1.0` with a comment asserting equality with
   `RECORD_KINDS.submission` — it is not equal, no test asserts it, and the value is
   syntactically invalid under the record-kind grammar.

## 4. Term dispositions

### 4.1 Keep, standards-aligned (no ruling needed unless the operator objects)

| Term | Standards anchor | Note |
|---|---|---|
| **evidence** (layer) | **RFC 9334 RATS**: "Evidence: a set of Claims generated by an Attester to be appraised by a Verifier" — structurally identical to Jinn's pipeline | The operator's challenge, answered: calling the raw record an "attestation" would be wrong under every surveyed standard (nothing is attested until a signed statement covers it). Gloss the SLSA "provenance" mapping in docs |
| **execution-verification** | SLSA Verification Summary Attestation; VC 2.0 verification-vs-validation split | Near-perfect match |
| **result-evaluation** | VC 2.0 validation; in-toto test-result predicate | "Evaluation" beats "validation": the Evaluator role and loop phase are canonical |
| **verdict** | Legal register; richer than VSA's PASSED/FAILED | Document the PASS→PASSED mapping once |
| **evidence tier** | SLSA Build Levels (same axis: cost-to-forge) | Optionally number tiers SLSA-style in docs |
| **trust** (layer) | Sigstore trust root; RATS appraisal policy | Prefer precise compounds (key binding, appraisal policy) in sub-surfaces |
| **task** | Marketplace/batch sense; Task→Attempt ≈ Tekton Task→TaskRun | State the analogy once in docs |
| **attempt** | GitHub `run_attempt`; Temporal attempt counters | Strongest term in the system — failure-neutral, which is the corpus's point |
| **delivery** | OLAS Mech's own `deliver` verb (the substrate) | Reserve "fulfillment/accept" language for any future acceptance concept |
| **task profile** | RFC 6906 profile link relation; FHIR profiles | The *term* is right; the namespace layering is the defect (§5.3) |
| **evaluation spec** | K8s spec/status convention | — |
| **requester / operator / evaluator** | OLAS-native (requester, service operator); "evaluator" ≠ SLSA "verifier" deliberately (graded judgment vs binary conformance) | See open question Q6 (Curator) |
| **plugin, artifact, checkpoint** | Universal / RO-Crate / stream-processing | Checkpoint: never bare in docs that also touch OLAS staking checkpoints |

### 4.2 Keep with a guardrail (ruling: confirm the guardrail)

- **submission** — requester-side by batch-computing precedent, but bounty/review readers
  assume worker-side. Guardrail: the operator-side artifact is *always* a Delivery, never a
  submission, stated in GLOSSARY.md. Renaming a frozen sealed family is not justified.
- **lifecycle observation** — every comparable system says "event"; Jinn's defense is
  epistemic (witnessed by a backend, folded as evidence, not commands) and avoids a
  two-layer collision with CloudEvents `event`, which the facts profiles already emit.
  Guardrail: glossary line "what other systems call a lifecycle event, named from the
  witness's side."

### 4.3 Disambiguate or converge — RULED (operator, 2026-08-04)

- **Q1 — "attestation" triple duty. RULED: keep the tier name `attested`; glossary
  disambiguation.** The operator's challenge corrected the draft recommendation
  (`tee-attested`): verification showed `AttestationSchema` carries a **`profile` field** —
  the attestation *mechanism* is pluggable by design, TEE quotes being the current profile,
  not the tier's definition. Renaming the tier would have narrowed a deliberately
  mechanism-neutral tier to one mechanism. "Attestation" stays for in-toto statements
  (normative upstream). Noted for the evidence owners, not renamed here: the current schema
  fields (`quote`, `reportData`, `measurement`) are TEE-quote-shaped — the schema is
  narrower than the tier's intent.
- **Q2 — "trajectory" vs "trace". RULED: full convergence.** The re-seal mints
  `records/trace/v1`, `jinn.trace.v1`, `profiles/trace-vocabulary/v1` for all new records;
  prose says "trace" everywhere. Pre-migration bytes keep saying `jinn.trajectory.v1`
  (content-addressed — unchangeable in principle) and readers keep recognizing the old
  strings as legacy input. Rationale for full rather than prose-only convergence: every
  identifier is being re-minted by the migration anyway, so keeping the rejected word in the
  new namespace would pay for a migration and keep the old name.
- **Q3 — "envelope". RULED: reserve for DSSE.** The legacy corpus SignedEnvelope exits with
  `packages/core` as already chartered; `records/delivery-envelope/1.0` is renamed in the
  migration; GLOSSARY.md's envelope entry (which currently matches neither code meaning) is
  corrected in the glossary pass.
- **Q4 — "claim". RULED: standing DR-2026-06-14 is the authority — no new decision.**
  That DR ratified: *claim is the verb (the act of reserving a slot), attempt is the noun
  (the record the claim creates)* — "the verb and the noun of one event, not two synonyms."
  The deployed contract already follows the split. The RFC 9334 collision resolves on top:
  evidence/trust prose says **"assertion," never "claim."**
- **Q5 — "execution-evidence". RULED: keep**; docs gloss it as "a provenance record of one
  execution" for SLSA/RO-Crate readers.
- **Q6 — demand-side role. RULED: requester, everywhere; no product-layer role term.**
  Verification showed the glossary's Curator entry is anchored to *launching a SolverNet* —
  a dissolved concept — so it is a stale definition, not a live competing name. The operator:
  "requester requests from the marketplace — we don't have to overthink it." The Curator
  role entry (and the "Curator funding" stream name) are corrected in the glossary pass via
  the canonical-doc process. (stOLAS "curating agent" is OLAS's own term and is untouched.)

### 4.4 Defects to fix in the migration regardless of naming rulings

- The `records/task-execution/{submission,delivery}/1.0` divergence (§3.3) — collapse to
  canonical kinds.
- Five task-supply record kinds with grammar-violating bare-integer versions.
- Orphan spellings of the TEP protocol URI (`tep/v1`, `tep/1.0`, `task-execution/1.0`,
  `protocols/task-execution/1.0`) — all normalize to the canonical profile URI.
- `agents/` vs `agent/` fixture drift — one spelling.
- 3-segment `$id`s under `records/` (`records/trajectory/1.0/schema`) — a record-kind URI
  must not be a directory prefix of a served document; re-home schemas under their profile.
- `trust/key-binding/v1` vs `records/key-binding/1.0` vs `trust/key-binding/1.0` — one
  format URI + one record-kind URI, one version convention, no third variant.
- The `corpus` collision (glossary: attempt collection; information-world: captured HTTP
  set) — rename the information-world field (`capture.entryCount` or similar); it is not
  sealed-published.
- GLOSSARY.md coverage: it claims canonical authority over Jinn terms but defines 4 of ~18
  protocol nouns, and "Attempt" — its headline unit — has no record kind. Glossary update
  rides the migration PR; whether an `attempt` record kind should exist is deferred to the
  protocol owners (not a naming question).

## 5. Namespace convention for the new origin (adopt/reject)

1. **Origin: `https://spec.jinn.network/`** (ratified). All protocol URIs, names and
   locators. The apex becomes purely product. The PWA `/manifest.json` collision disappears
   with the origin move.
2. **Version segments: major-only `/v1`, uniformly, for type/protocol identifiers.**
   Adopted from SLSA/in-toto (major-only TypeURIs) and atproto Lexicon (breaking = new
   name); our dominant `/1.0` contradicts our own identifier law (a compatible 1.0→1.1 must
   not change the identifier; a breaking one is `/v2`). The discovery grammar's
   `major.minor` regex changes with it. **Exception, named:** task-profile *instances* are
   digest-pinned artifacts where the revision is part of the name (`repository-work/1.1` is
   distinct sealed content); their URIs keep a full revision, and the digest — not the URI —
   does the pinning, resolved via the root manifest.
3. **Shape: plural container segments, singular lowercase-kebab type names, exactly one
   version segment, last.** Fixes the `profile/` singular outlier, the `records/Task`
   case outlier, and nested versions (`records/authorization/1.0/facts/1.0` — facts
   profiles become their own identifiers, e.g. `facts/authorization/v1`).
4. **Collapse the "profile" pile-up** (six senses today): `profiles/<name>/v1` for document
   formats; `task-profiles/<name>/<rev>` for work-class instances; facts profiles to their
   own namespace; retire the `records/<kind>/…/facts/…` nesting and the
   `facts-profile` spelling variant.
5. **Identifier hygiene (XML-namespace lessons):** one canonical string form (https,
   lowercase host, no trailing slash), byte-exact comparison, never normalized; the spec
   states explicitly that identifiers are names first and dereference as a service;
   "Cool URIs" permanence commitments written into the namespace's governing section.
6. **Root manifest stays** (npm packument / OCI index / RFC 8615 precedent) at
   `spec.jinn.network/manifest.json`, and is where `/v1` → current revision + digest
   resolution lives.
7. **Rejected:** reverse-DNS identifiers (ours are https TypeURIs in the in-toto mold;
   reverse-DNS stays only in CloudEvents `type` values, a wire mapping, not a namespace);
   date-based versions; a w3id-style indirection layer (single org-controlled origin).
