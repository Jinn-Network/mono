# Scoring tables — quick numeric reference

Look up here. Don't reinvent. For mechanism behind each number, see `algorithm-model.md` § cited.

Every multiplier is "vs the median text post for an account at this Tweepcred level". Use the midpoint of any range unless context says otherwise.

---

## 1. Format multipliers (model §4)

Engagement-rate multiplier (not raw reach). Native short video has a separate raw-reach lift noted in parentheses.

| Format                          | Multiplier (rate) | Notes |
|---------------------------------|-------------------|-------|
| Text post (no media)            | 1.0               | Baseline |
| Text + image                    | 1.2               | Image stops scroll |
| Text + diagram/screenshot       | 1.3               | Information-dense images outperform decorative ones |
| Thread (3–5 tweets)             | 1.5 (total)       | More aggregate impressions |
| Thread (7–12 tweets) — sweet    | 1.5–1.6           | Bookmark-driven reach |
| Thread (13+)                    | 1.0–1.2           | Drop-off, fatigue |
| Native short video <2 min       | 0.7 rate / 1.7 reach | Push for raw impressions, lower rate |
| Long-form post / Article        | 1.3 (Premium-only) | Dwell-time rewarded; high variance |
| Poll                            | 0.7               | Low-quality engagement |
| Quote tweet (substantive)       | 1.1               | Riding host's velocity |
| Quote tweet (just "this")       | 0.5               | Algorithm reads as low-effort |

## 2. Length zones (model §5)

Character count of the main post (not the whole thread).

| Length (chars) | Multiplier | Zone label |
|----------------|------------|------------|
| 1–70           | 0.8        | Too thin |
| **71–100**     | **1.3**    | Sharp zone — claims, hot takes |
| 101–239        | 1.0        | Dead zone — flag for cut or extend |
| **240–259**    | **1.2**    | Depth zone — substantive |
| 260+ (Premium long-form) | 0.9–1.4 | High variance; depends on dwell |

**Rule for the skill.** Drafts in the dead zone (101–239) should be flagged. Recommend either cutting to ≤100 (sharper claim) or extending to 240–259 (more depth). Don't pick for the user; show the trade-off.

## 4. Tone overlay — Grok layer (model §11)

INFERRED multipliers. Calibrate against own posts over time.

| Tone | Multiplier | Markers |
|------|------------|---------|
| Constructive + specific | 1.1–1.2 | Names a mechanism; offers a position; respects the counter |
| Neutral / informational | 1.0 | Reports without colour |
| Mildly provocative | 0.9–1.0 | Strong claim without contempt |
| Combative / dismissive | 0.6–0.8 | Scare quotes, "people who think X are wrong" |
| Contemptuous / sneering | 0.5–0.7 | Stacked rhetorical questions, second-person accusation |
| Abusive / harassment-shaped | hard kill | See model §3 |

**Auto-flags for the skill:**

- Second-person accusations ("you don't get it", "people who say X are…")
- Scare quotes used dismissively
- Stacked rhetorical questions (>1 in same post)
- Lead-with-dismissal ("Sigh, …", "No,", "Wrong,") before the claim

## 5. Author-reply-trap quality (model §2)

The single dominant signal. Score the post's *invitation* to reply, not the post itself.

| Pattern | Multiplier | Examples |
|---------|------------|----------|
| Open question that names a real tension | 1.0 | "What's the architecture of the layer where all that work happens?" |
| Contestable claim with a named counter to attack | 0.9 | "Centralised AI captures value at the model layer. Where does this break?" |
| Specific gap or admission | 0.8 | "I don't have a good answer to X. Anyone closer to this?" |
| Strong assertion that invites pile-on without reply | 0.5 | "Decentralised AI is inevitable." (people will like; few will reply substantively) |
| Pure broadcast (announcement, news) | 0.3 | "We launched X today." |
| Closes the loop cleanly | 0.3–0.4 | A complete argument with no opening |
| Shitpost / engagement bait without substance | 0.2 | (also tone-penalised) |

**Quick test.** Read the post and ask: "If a respected operator in the cluster replied, would I have a substantive reply ready?" If yes — high score. If no — closes the loop.

## 6. Velocity plan (model §10)

Three levers; add 0.2 per lever applied. Floor 0.5, ceiling 1.0.

| Lever | Description |
|-------|-------------|
| Peak window | Tue–Thu, 09:00–14:00 target-tz (US/EU for Oak's cluster). Weekend dead. Evenings drop. |
| Self-reply at +5 min | Adds context, links, quote, or a deliberately provocative extension that re-fires the +75 mechanism |
| Pre-warm allies | 2–5 cluster-relevant accounts notified the post is coming. Not pod-style — bilateral. |

| Levers applied | Multiplier |
|----------------|------------|
| 0 | 0.5 |
| 1 | 0.7 |
| 2 | 0.85 |
| 3 | 1.0 |

## 7. Penalties (model §14)

Each penalty multiplies into the score. Stack as needed.

| Penalty | Multiplier | Detection cue |
|---------|------------|---------------|
| External link in main post | 0.1–0.5 | Hard kill — see model §6, §3 |
| Hashtag stuffing (>2) | 0.8 | Count `#` in post |
| Cross-platform watermark | 0.7 | TikTok logo, IG branding, etc. |
| Near-duplicate to last 7 days | 0.6 | Compare against own recent feed |
| Link shortener (bit.ly etc.) | 0.7 | Pattern match |
| Posting velocity spike (>5/hr) | 0.7 | Cadence check |
| Thread without internal cohesion | 0.8 | Each tweet stands alone with no link/build |
| Trending hashtag without genuine relevance | 0.5 | Topical drift |

## 9. Smart-follower weighting (model §12)

ANECDOTAL but directionally consistent. Use only as a cue for reply-target selection, not for predicting reach of a draft.

| Engager type | Cluster lift per engagement |
|--------------|------------------------------|
| Premium + cluster-central operator | High (10–100x casual) |
| Verified, adjacent cluster | Medium (5–20x) |
| Unverified, in-cluster, active | Medium (3–10x) |
| Random / off-cluster | Low (1x or less) |

## 10. Scoring formula (multiplicative)

```
draft_score =
    cluster_fit
  × format
  × length
  × tone
  × author_reply_trap
  × velocity_plan
  × penalty_product
```

`penalty_product` defaults to 1.0; multiply by each detected penalty's multiplier.

Account multipliers (Premium, Tweepcred, smart-follower base) are reported separately so the user can see what the post earns *given* the account context. The skill should not roll them into the per-draft score — different decisions hang off them.

**Score interpretation:**

| Range | Action |
|-------|--------|
| 0.7–1.0 | Ship |
| 0.4–0.7 | Lift binding constraint, then ship |
| 0.0–0.4 | Substantial rework — name the two lowest factors and propose edits to both |

## 11. When the model is uncertain

Sections in `algorithm-model.md` flagged INFERRED or ANECDOTAL: the skill should output the score but include a one-line caveat. Examples:

- Tone multiplier (Grok overlay) — INFERRED. Calibrate from observed posts.
- Smart-follower lift — ANECDOTAL. Track engagers, don't predict.
- Cluster cold-start crossing — INFERRED. Worth A/B testing.
- Revival window — INFERRED. The model may under-predict late-rising posts.

Cite the tier in the EDIT line whenever the binding constraint is supported only by INFERRED or ANECDOTAL evidence.
