# A4 (#1818) — Delete wizard + consent surfaces; relocate the `◇` renderer — design note

- **Shape:** `refactor` · Python-plugin-only · stacked on #1817 (doctor).
- **Spec:** `docs/superpowers/specs/2026-07-17-jinn-plugin-onboarding-design.md` §3.5.
- **Worktree:** `jinn-mono_worktrees/1818`, all paths under `apps/jinn-agent/`.

## Chosen approach

Delete the outbound/consent/wizard surfaces and their dead helpers, relocate the one
production-shared renderer (`render_evidence_signal_line`) into a **new view module
`corpus_view.py`**, and slim `/jinn status` to the parked line. Keep `consent.py` and
`skills_install.py` as modules — **the spec's "zero callers" claims for both are stale on this
branch** (evidence below); only their *outbound* entry points are removed. The result is
structurally fail-closed: after this change no reachable code path can call `jinn-layer publish`,
`contribution_preview`, `contribution_disable`, `set_publication_enabled`, or the ledger surface.

Two spec deviations, both driven by code evidence, are recorded in "Risks / spec corrections"
and should ride the PR body so C-track and the meta session see them.

## First-session-banner alignment with A3 (#1817)

A3 already shipped the banner-marker mechanism this issue's spec anticipated. **No new marker is
invented; A4 only deletes the old flag machinery.** On this branch:

- Marker file: `doctor._first_session_marker_path()` → `<home>/jinn/first-session-done`
  (`doctor.py:247`), gated by `_first_session_done()` / `_mark_first_session_done()`.
- Banner content: `doctor.first_session_banner(checks)` (`doctor.py:267`), emitted from
  `_on_session_start` (`__init__.py:236-247`).

So `onboarding.py`'s `onboarding.json` flag file (`state_path`, `load_flags`, `mark_flag`,
`signals_shown`) is fully orphaned once `onboarding.py` is deleted — the banner marker already
replaced it. Nothing in A4 needs to write a marker.

## Relocation target for `render_evidence_signal_line`

`render_evidence_signal_line` (`onboarding.py:344-376`) is the `◇ corpus` line. Production caller:
`pickup.py:89-90` (`from . import onboarding` local import → `onboarding.render_evidence_signal_line`).
It depends only on `style` (`_style.palette/wrap/sanitise`) — no consent/ledger/harness coupling —
so it relocates cleanly.

**Target: a new `corpus_view.py`** (sibling of `session_view.py`, `history_view.py`, `ledger_view.py`;
matches the repo's `*_view.py` convention and the spec's "moves to a view module"). `pickup.py`
then does `from . import corpus_view` at module top (the local-import cycle-avoidance dodge in
`pickup.py:89` existed only because `onboarding.py` imported heavy siblings; `corpus_view.py` will
not, so the top-level import is safe). Put the module docstring's single source-of-truth note there.

Rejected alternatives: (a) fold into `style.py` — `style.py` is pure ANSI primitives, a
semantic corpus line does not belong; (b) move into `pickup.py` itself — the spec explicitly wants
a *view module* and tests import the symbol independently.

## Risks / spec corrections (surface in the PR body)

1. **`skills_install.py` is NOT dead** (spec §3.5 says "zero callers"). Live callers:
   `distill.py:93,336,496,517,699,725` (`skills_dir()`) and `__init__.py:828`
   (`_extract_trace` via `_tool_corpus_fetch`). **Do not delete it.** `skills_install.py:52-56`
   itself documents these as RESIDUAL read-only helpers pending a harness-layer follow-up. A4
   removes no code from this file.
2. **`ledger_view.py` has an out-of-plugin caller:** `hermes_cli/banner.py:920-927`
   (`_read_contribution_count`) imports `plugins.jinn.ledger_view` for the splash's published
   count. It is fully try/except-guarded (`banner.py:928` → returns `None`), so deleting
   `ledger_view.py` degrades the splash count to absent without raising. **Also** `banner.py:397-399`
   reads `consent.consent_decided/share_enabled` (guarded, 401-402). These host-side reads sit
   outside A4's Python-plugin scope but must be acknowledged: deleting `ledger_view` is safe only
   because of the guard. Cleanest: in the same PR, drop the dead
   `banner._read_contribution_count` + its `contribution_count` merge (a few lines in `banner.py`,
   still Python) so we don't leave an import of a deleted module even inside a try. Flag for meta
   review since `banner.py` is host CLI, not plugin.
3. **Dangling-import sweep:** after edits, grep `apps/jinn-agent` for `onboarding`, `ledger_view`,
   `render_skipped_all`, `render_evidence_signal_line`, `jinn_layer.publish` and confirm the only
   hits are the new `corpus_view` + `pickup` pair and unrelated host modules
   (`agent/onboarding.py`, `hermes_cli/*onboarding*` are the host's own unrelated onboarding — do
   NOT touch).
4. **Convergent file:** `__init__.py` is edited by both A3 (landed) and A4. All A3 doctor/banner
   lines (imports, `_on_session_start` doctor block, `/jinn doctor` branch, `jinn-doctor` CLI
   registration) must be preserved verbatim; A4 only removes consent/preview/ledger/onboarding.
