## Context

Legitimacy for an official suite is that **their** method ran. Terminal-Bench
2.1 locked Harbor 0.21 under that rule. DeepSWE v1.1 is the next named
protocol: Datacurve's published method is Pier driving **mini-swe-agent** on
the git-pinned Harbor-format `tasks/` tree (113 tasks), with an isolated
verifier (`[[verifier.collect]]`, Pier newer than 0.3.0). The v1 paper sampled
about four independent rollouts per task; the v1.1 site still reports Pass@1
±CI. That is the TB 2.1 pattern (lock their published n_attempts), not the
SWE-bench Verified pattern (k=1 because that is their official eval).

Harbor 0.21 cannot wear this name: `allow_internet = false` on these tasks
blocks LLM APIs, which is why Pier exists. Pier driving Claude Code, Codex,
gemini-cli, or opencode is a cousin. DeepSWE v1 (shared verifier env) is a
cousin. k=1 is a cousin.

Submit is email to Datacurve (`serena@datacurve.ai`). There is no Hub /
`lb submit`. Colophon does not place the row. The checkable claim of record
remains the Colophon/Jinn bundle; a Pier job tree is a derived inspection
artifact for that email.

## Decisions

1. **Named protocol is DeepSWE v1.1**, not v1.0. Dataset is the local
   Harbor-format tree from `datacurve-ai/deep-swe` `tasks/` at git commit
   `435ee89ec2f2e2289f33b0da4f992f0b7b7266b9` with git tree SHA of `tasks/`
   `66df25a1b382017d0ae014d94cadb2698baaed48`. Do not pin `@latest`. Pier does
   not resolve Harbor registry datasets.

2. **Runtime is Pier** (`datacurve-pier` **0.3.1.x**), adapter id `pier`. Not
   Harbor 0.21. Agent is **mini-swe-agent only**, model-agnostic, shared
   prompt/loop. Environment is Pier `docker` or `modal`. Modal is Datacurve
   compute, not a protocol bit. No CPU/memory/GPU/mount overrides. Wall-clock
   sanity bound **9000s** per trial; no step/cost cap.

3. **Official trial settings.** Planned trials k ≥ 4 per selected task.
   Default select is k=4. Extra sampling may keep the name. **k=1 cannot wear
   `deep-swe-v1.1`.** Pier `retry.max_retries` is **3**, matching the TB 2.1
   salvage rule: each planned trial is one TEP Submission with
   `attempts.maxTotal = 1`; a Pier retry that starts work is the next Colophon
   dispatch on that cell, not an extra replicate.

4. **Comparability is two-axis** and protocol-specific. Report v2 gains no new
   required fields. A sealed product `SuiteProtocolSelection` variant
   `protocol: "deep-swe-v1.1"` binds through the existing Run publication
   extension. Surface:
   - `execution_conformance` — Pier 0.3.1.x, mini-swe-agent, k≥4, official
     env, per-arm job grain;
   - `coverage` — `one_task` | `ten_task` | `full` | `custom` (lexicographic
     first 1 / first 10 / all task directory names from the pinned tree);
   - `leaderboard_submit_ready` — `full` and `execution_conformance` and every
     dataset task × 4 accounted after collect as judged or Pier-error 0
     (provider/verifier/network errors are excluded from the metric per paper
     §5.6 but **accounted**), ATIF bytes on the retained Pier job, and
     per-trial `reward.json` (missing reward = unscorable, not skip).
     Quote/lock method bits never set this true.
   When not `leaderboard_submit_ready`, Report `limitations[]` carries a
   canonical sentence that names **DeepSWE v1.1**, not Terminal-Bench or
   SWE-bench.

5. **One Pier Job per arm** spanning that arm's selected tasks × k planned
   trials. The launcher waits in-process (`spawnSync` / follow), not detached
   `unref()`. Job identity is Run + arm. Each Trial binds 1:1 to a pre-sealed
   cell as it starts.

6. **Pier export is a derived artifact, not the claim of record.** From a
   `leaderboard_submit_ready` run, emit a retained Pier job tree for the
   Datacurve email flow. Named-slice protocol-faithful runs may export for
   inspection and must not be packaged as a leaderboard submission. Custom /
   unverifiable / non-DeepSWE locks refuse suite-named DeepSWE export. Copy
   must say Colophon does not place the Datacurve row.

7. **Metric.** pass@1 is the macro-average of per-task pass fractions. pass@4
   is a derived view of the same four cells, not a second protocol. Do not use
   `binary-instrument` majority-k.

8. **Quote before full-suite lock.** Quote shows `tasks × arms × k`, Pier
   version, and the three comparability bits. A full-suite lock without that
   quote is refused. CI never downloads the 113-task tree and never invokes
   real Pier.

9. **Out of this train.** TB 3.0, APEX, Inspect-as-specified, Pier+Claude Code
   as a named protocol, mini-swe-agent LM track for SWE-bench Verified, live
   full-113 in CI, and placing a Datacurve leaderboard row.

## Consequences

- `SuiteProtocolSelection` is a discriminated union. TB 2.1 and DeepSWE v1.1
  each own their limitations sentences and conformance helpers.
- GTM may describe DeepSWE v1.1 as a named protocol Colophon wraps. A cousin
  method on DeepSWE tasks still cannot wear the suite name.

## Alternatives rejected

- **Harbor 0.21 on these Harbor-format tasks.** Internet-off Harbor cannot
  reach model APIs; that is why Pier exists.
- **k=1 as the official eval.** DeepSWE publishes pass@1 with a run-to-run CI
  from multiple rollouts; k=1 is Harbor's default, not their method.
- **Pier+native CLIs as the named protocol.** The leaderboard method is
  mini-swe-agent.
- **New required Report v2 fields.** Comparability stays product-private plus
  existing `limitations[]`.

## Ratification

Ratified on 2026-08-18 by the operator's instruction to implement the
attached DeepSWE v1.1 official-suite train. Changing the Pier pin, wearing the
suite name on a cousin method, or placing a Datacurve row from Colophon
requires a superseding record.
