Corpus tab

A new top-level tab in the network explorer: browse the contributed task-trace corpus, open one item, and reach its IPFS content and on-chain anchor. Composed entirely from the explorer's existing primitives (Chrome, DataTable, StatusChip, Card, StatusBar). Every item has a stable deep-linkable URL — /corpus/:cid — the seam the CLI's "view your contribution" step (#1405) lands on.

Design notes — 1406 Corpus tab

Placement — fourth primary nav item

The spec (§4) left open whether Corpus becomes a fourth tab or stays a Network-view sub-route. Designed here as a top-level tab — Network · SolverNets · Operators · Corpus. Rationale: the corpus is the network's product (the loop's Knowledge output), peer to its actors (Operators) and its programs (SolverNets); and the CLI deep-links operators straight into it, so it needs a first-class home, not a nested view. The #1407 summary card co-exists on the Network view and links here.

Routes & URL state

  • /corpus — index. Sort key/direction, page, and the seed filter live in the query string per §3.3 (?sort=createdAt&dir=desc&page=1&include=raw), so every slice is shareable.
  • /corpus/:cid — detail, keyed by the envelope's content CID. Stable and deep-linkable: the CLI's jinn-agent ledger and the first-run "view your contribution" step (#1405) print exactly this URL. Unknown CID → the soft not-found state.

No new primitives. The only additions are data: three tier kinds on StatusChip's map and a route pair.

Seed provenance — a per-item fact, not a filter

The seed toggle is retired from both this tab and the Network card (#1407). The index and every count show contributed traces only (the backend's envelope-only default, spec §3.2). Where an envelope was imported, that's a fact about the one item, so it renders on the detail's meta row: Provenance · contributed for network-produced traces, imported seed (in --wane) for seeded ones — whose index rows also stay out of the default listing. An audit view of seeds, if ever needed, belongs behind ?include=raw, not in the primary UI.

Tier chips — colour without breaking one-gold

  • user-accepted — sky (--accent). The operator marked it done; no automated check.
  • tests-passed — green (--vow-green). The task's own suite passed.
  • evaluator-verified — muted gold (--gold-600) — the same muted lamplight StatusChip already uses for frozen, so a column of chips never competes with the surface's single --gold-400 hero (the corpus total on the index; none on the detail unless the tier itself is the emphasis).

Same ordering and colour logic as the CLI ledger (#1312) — the two surfaces state tiers identically.

Tool steps — summarised sequence, payload on demand

The spec's open question (§4: raw vs summarised) is resolved as both, layered: each row is a one-line summary (tool · outcome), and expanding shows the scrubbed args/result pair from the envelope. A failed intermediate step renders in --wane — attempts are part of the record, per Learning Maximised; the corpus shows search, not curated success. The full raw payload is one click further, via the IPFS content link.

Pagination & sorting

Newest-first by default (createdAt desc); sortable on Cluster, Tier, Age, consistent with the roster tables' header-click behaviour. Paged 10 per page with Prev/Next — the corpus grows unboundedly, so unlike the rosters it cannot render whole. Page state in the URL.

The seam with #1405

The detail frame renders the same envelope the CLI first-run flow publishes (fix flaky retry in http client, tier tests-passed, contributor 0x91be…44a2) — the trace previewed in the 1312 consent flow, published in 1405 step 2, landing here. One item, three surfaces, identical fields.

Open questions

  • Contributor link target. Shown linking to /operator/:addr. Correct only if contributors are always operators; if apps can contribute, this needs a contributor concept. Flagged.
  • Cluster chip as filter. Clicking a cluster chip could filter the index (?cluster=…). Deferred — needs the filter-chip strip; the primitive exists.
  • Steps column. The index shows a step count; it's derivable, not in the spec item shape. Drop if the endpoint doesn't carry it.
