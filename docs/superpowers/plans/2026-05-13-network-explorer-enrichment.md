# Network Explorer — IPFS Envelope-Enrichment Plan (ebu7.6)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or executing-plans. Steps use `- [ ]`.

**Goal:** Add the envelope-sourced dimensions to the explorer — harness identity (`implName`/`implVersion`/`codeDigest`), train/frozen `mode`, plugins, model (originating tool), and the `HarnessCheckpoint` timeline + freeze integrity — by (a) indexing `harness.checkpoint:*` metadata on-chain (cheap), and (b) an IPFS-enrichment step that fetches each execution envelope and stores its `executor` block joined to the attempt by `requestId`. Extend the `/explorer/*` routes with the new facets.

**Architecture:** The `attempt`/`verdict`/`task` entities and the `/explorer/*` routes already exist (ebu7.2/7.3). This bead adds: a `harnessCheckpoint` `onchainTable` populated by routing `IdentityRegistry.MetadataSet` keys with prefix `harness.checkpoint:` in the existing `handleMetadataSet`; a small `src/ipfs.ts` helper; an `attemptEnvelopeMeta` `onchainTable` populated by an **async IPFS fetch+parse inside the `envelope:` branch of `handleMetadataSet`** (resilient: timeout, catch → mark failed; gated by `JINN_INDEXER_ENRICH_ENVELOPES` env, default on); and additions to `src/api/explorer.ts` (+ `src/api/metrics.ts` helpers) that join `attemptEnvelopeMeta` for the mode/harness/plugin/model facets, the train/frozen leaderboard split, the checkpoint timeline, and a query-time freeze-integrity computation. The `HarnessRollup`/`LanguageRollup`/`FreezeViolation` "entities" the design names are computed at query time from `attemptEnvelopeMeta × verdict × attempt`, not materialized (consistent with the design's compute-on-read default; materializing them is a follow-up if perf needs it).

**Tech stack:** Ponder 0.16.6, Hono 4, viem, Zod (for parsing the envelope/checkpoint manifest — a loose local schema, not the full `client/src/types/envelope.ts`), Vitest 2. IPFS gateway default `https://gateway.autonolas.tech` (matches `client/src/config.ts`), env-overridable.

**Reference:** design `docs/superpowers/specs/2026-05-12-network-explorer-design.md` §4.2, §5, §6; envelope shape `client/src/types/envelope.ts` (`SignedEnvelopeSchema` — `solverType`, `executor.{implName,implVersion,codeDigest,plugins,mode,source}`, `sessionProvenance.{originatingTool,repo}`, `task.{cid,requestId,onchainCreationTx,onchainCreationBlock}`); checkpoint key + manifest `client/src/cli/commands/checkpoint.ts` (`harness.checkpoint:<manifestPinCid>`, `HarnessCheckpointManifestSchema` from `@jinn-network/sdk/checkpoint` — `{schemaVersion:'harness.checkpoint.v1', name, version, parentCheckpointCid, harnessPackage:{implName,implVersion,clientGitSha,sourceBundleCid}, implStateDirCid, codeDigest, publisher:{agentId,signingKey,safeAddress}, publishedAt, registry, signature}`); IPFS fetch pattern `client/src/adapters/mech/ipfs.ts` (`fetchFromIpfs(gatewayBase, cid)` — normalizes base to end with `/ipfs/`, fetches `<base>/ipfs/<cid>`).

**Conventions:** Run-mode `feat`. Work in this worktree. bd: `jinn-mono-ebu7.6` (already claimed + in_progress). Commit per task, prefix `feat(ebu7.6): ...`. No co-author lines on per-task commits.
