# Hot-apply a SolverNet join to the running daemon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a SolverNet join applied to a *running* daemon take effect within one claim poll — no process restart — by sharing the per-join registration logic between the boot path and a live `applyJoin(entry)` applier wired through a holder.

**Architecture:** Four subsystems consume `joinedSolverNets`. Two already re-read their config object live (the `MechAdapter` task-discovery cid array and the engine's `JoinedSolverNetsView`); two are frozen at construction (the `HarnessReadinessRegistry` cid→harness map and the `SolverNetRegistry`). The fix: (1) always construct the live-updatable surfaces even at zero joins, (2) back the engine view with a mutable Map, (3) give the readiness registry a single-entry setter, (4) extract the boot loop's per-join registration into a shared exported function, (5) add a `client/src/daemon/join-applier.ts` `applyJoin(entry)` that mutates all four live instances (plus the in-memory `config.joinedSolverNets`), (6) wire it via a `joinApplierHolder` in `main.ts` populated after the last subsystem is built, mirroring the existing `harnessReadinessRegistryHolder` / `discoveryApiHolder` / `solverNetEndpointsDepsHolder` eager-register/late-populate pattern, and (7) have `POST /v1/operator/join/:cid` call the applier after the config write and return `restartRequired: false` when it succeeds.

**Tech Stack:** TypeScript (ESM, NodeNext), Vitest, Hono. All paths under `client/`.

## Premise validation (done before this plan was written)

Every design premise was checked against the worktree `feat/1037-hot-apply-join` (off `origin/next`). All hold:

- **Adapter re-reads config live.** `client/src/adapters/mech/adapter.ts:230` stores `this.config = config` by reference; `discoverSubgraphRestorationTasks` (`:780-787`) reads `this.config.taskDiscovery.solverNetManifestCids` per call and early-returns when the array is empty (`:787`). Pushing onto the live array works.
- **Engine view is a per-task closure.** `client/src/harnesses/engine/engine.ts:930-988` (`evaluateJoinedEligibility`) calls `view.get(cid)` / `view.manifestCids()` each time; `joinedSolverNetsViewFromConfig` (`:153-168`) builds the view from a `Map` snapshot at construction. Backing that Map with a mutable instance the applier holds makes it live.
- **Readiness map is frozen at construction.** `client/src/harnesses/readiness-registry.ts:84` `getJoinedHarnessesByCid()` returns the live `this.opts.joinedHarnessesByCid` object; `_doRefresh` (`:124-127`) seeds every *registered harness* into the snapshot regardless of joins, so a newly-joined cid pointing at an already-installed harness is ready the moment its map entry exists — no new probe.
- **Registry `register()` is public.** `client/src/solver-nets/registry.ts:176`. The boot loop's per-join body is the inner `registerFromConfig` + the `for (const [cid, joined] …)` loop at `:282-304`.
- **Holder pattern exists.** `client/src/main.ts:1043-1067` declares `solverNetEndpointsDepsHolder`, `harnessReadinessRegistryHolder`, `discoveryApiHolder`; the routes register eagerly inside `startApiServer` (called at `:1079`, with `setup` wired at `:1278`) and `holder.current` is populated after each subsystem is built.
- **Subsystem build order.** taskDiscovery / `MechAdapter` at `:1797-1831`; `SolverNetRegistry` + engine deps `solverNetRegistry` at `:1907` and `:2563`; engine `joinedSolverNets` view at `:2570-2572`; `HarnessReadinessRegistry` at `:2028-2039`. The latest of the four is the engine wiring (~`:2570`), so the `joinApplierHolder` must populate after that.
- **Join endpoint.** `client/src/api/setup-endpoints.ts:456-610`; it builds `entry` (`:576-593`), persists via `persistConfigValue('joinedSolverNets', …)` (`:596`), returns `restartRequired: true` (`:606`). `addSetupRoutes(app, config: SetupRoutesConfig)` is the only entry point (`:114`); called once in `client/src/api/server.ts:616`; threaded from `main.ts:1278`.
- **Config shape.** `client/src/config.ts:473-494` types `joinedSolverNets` as `Record<string, JoinedSolverNetConfig>` exactly matching the `JoinedSolverNetConfig` interface (`registry.ts:28-37`). The endpoint's persisted `entry` is this shape.

## Premise that needs an explicit behaviour-change note (does NOT block — flagged)

**Always-constructing the engine view changes zero-join behaviour.** Today the engine `joinedSolverNets` view is wired only when `config.joinedSolverNets` is truthy (`main.ts:2570` conditional spread). When *absent*, `engine.ts:1018` `if (this.joinedSolverNets && task)` short-circuits and the engine falls back to the legacy solverType gate. If we always construct an (initially empty) view, a zero-join daemon flips from "legacy solverType fallback" to "joined-gate active". With an empty view, `evaluateJoinedEligibility` (`engine.ts:939-954`) *rejects* any task carrying a `solverNetManifestCid`, but *passes through* (returns `null` → legacy gate) any task with neither cid nor digest (`:983-987`).

This is safe and aligned with the AC because a zero-join daemon's task-discovery cid set is also empty, so the adapter discovers nothing to feed `canAcceptTask` anyway; and the AC explicitly wants a zero-join daemon to claim *nothing* until a join is applied. The only newly-rejected case is a CID-bearing task arriving through a non-discovery path on a zero-join daemon — which should be rejected. **Capture this in a regression test (Task 5)** so the change is intentional and visible.

```typescript
/**
 * Register a single joined SolverNet into `registry`, reproducing exactly the
 * derivation + plugin-resolution the boot loop runs (default-plugin seeding,
 * harness defaulting, role mapping). Shared by `loadSolverNets` (boot) and the
 * live join applier (`daemon/join-applier.ts`) so the two paths cannot drift.
 *
 * No-ops when the joined entry has no resolvable contract or no roles.
 */
export async function registerJoinedNet(
  registry: SolverNetRegistry,
  cid: string,
  joined: JoinedSolverNetConfig,
): Promise<void> {
  if (!joined.contract) return;
  const solverType = `${joined.contract.id}.${joined.contract.version}`;
  const contract = getSolverNetContract(joined.contract);
  if (!contract) return;
  const roles = rolesFromJoinedConfig(joined);
  if (roles.length === 0) return;
  const disabledDefaults = joined.disabledDefaultPlugins ?? [];
  const defaultPlugins = defaultRuntimePluginsForSolverType(solverType)
    .filter((plugin) => !defaultPluginDisabled(plugin, disabledDefaults));
  const harness = joined.roles.includes('solver')
    ? joined.harness ?? CLAUDE_CODE_HARNESS
    : evaluatorHarnessNameForContract(contract) ?? joined.harness ?? CLAUDE_CODE_HARNESS;

  const net: SolverNetConfig = {
    enabled: true,
    solverType,
    roles,
    harness,
    ...(joined.model ? { model: joined.model } : {}),
    plugins: [...defaultPlugins, ...(joined.plugins ?? [])],
    taskGenerator: { enabled: false },
  };

  const runtimePlugins: RuntimePlugin[] = [];
  const seenSources = new Set<string>();
  const seenNames = new Set<string>();
  async function addRuntimePlugin(
    entry: SolverPluginEntry,
    provenance: RuntimePlugin['provenance'],
  ): Promise<void> {
    const plugin = await resolveSolverPlugin(entry);
    if (seenSources.has(plugin.source) || seenNames.has(plugin.name)) return;
    if (!isRuntimePlugin(plugin) && !plugin.supports.includes(net.solverType)) {
      throw new Error(
        `SolverNet ${joined.name ?? cid} runtime plugin ${plugin.name} solverType mismatch: config=${net.solverType} plugin supports=${plugin.supports.join(',')}`,
      );
    }
    runtimePlugins.push(runtimePluginFrom(plugin, provenance));
    seenSources.add(plugin.source);
    seenNames.add(plugin.name);
  }
  for (const entry of [JINN_NETWORK_TOOLS_PLUGIN]) {
    await addRuntimePlugin(entry, 'default');
  }
  for (const entry of net.plugins ?? []) {
    await addRuntimePlugin(entry, 'configured');
  }
  registry.register({
    name: joined.name ?? cid,
    enabled: net.enabled,
    solverType: net.solverType,
    roles: rolesFromConfig(net),
    contract,
    harness: canonicalHarnessName(net.harness),
    ...(net.model ? { model: net.model } : {}),
    runtimePlugins,
    taskGenerator: net.taskGenerator,
  });
}
```

Add the new factory directly below it:

```typescript
/**
 * Mutable `JoinedSolverNetsView` for the running daemon. Unlike
 * `joinedSolverNetsViewFromConfig` (boot snapshot), the applier
 * (`daemon/join-applier.ts`, #1037) keeps a handle and calls `set()` when a
 * join is hot-applied, so the engine's per-task eligibility check sees the new
 * cid on its next call without a restart.
 */
export function createMutableJoinedSolverNetsView(
  initial: Record<string, { manifestCid: string; roles: Array<'solver' | 'evaluator'> }> | undefined,
): JoinedSolverNetsView {
  const map = new Map<string, { roles: Array<'solver' | 'evaluator'> }>();
  for (const [key, entry] of Object.entries(initial ?? {})) {
    map.set(entry.manifestCid ?? key, { roles: entry.roles });
  }
  return {
    get: (cid: string) => map.get(cid),
    manifestCids: () => [...map.keys()],
    set: (cid, entry) => { map.set(cid, entry); },
  };
}
```

```typescript
/**
 * Hot-apply a SolverNet join to the RUNNING daemon (#1037).
 *
 * Four subsystems consume `joinedSolverNets`. Two re-read their config object
 * live (the MechAdapter task-discovery cid array and the engine's
 * JoinedSolverNetsView); two are frozen at construction (the
 * HarnessReadinessRegistry cid→harness map and the SolverNetRegistry). This
 * applier mutates all four on the live instances so a join applied to a
 * running daemon takes effect within one claim poll — no restart.
 *
 * Wired in main.ts via `joinApplierHolder` (eager-register/late-populate,
 * mirroring harnessReadinessRegistryHolder). The join endpoint
 * (POST /v1/operator/join/:cid) calls it after writing config to disk.
 */

import type { HarnessReadinessRegistry } from '../harnesses/readiness-registry.js';
import type { JoinedSolverNetsView } from '../harnesses/engine/engine.js';
import {
  SolverNetRegistry,
  registerJoinedNet,
  rolesFromJoinedConfig,
  type JoinedSolverNetConfig,
} from '../solver-nets/registry.js';
import { CLAUDE_CODE_HARNESS } from '../harnesses/names.js';

export interface JoinApplierDeps {
  /** The MechAdapter's live taskDiscovery object (cid array is pushed onto). */
  taskDiscovery: { solverNetManifestCids: string[] };
  /** The engine's mutable joined view. */
  view: JoinedSolverNetsView;
  /** The live readiness registry. */
  readiness: HarnessReadinessRegistry;
  /** The live SolverNet registry. */
  registry: SolverNetRegistry;
  /** The in-memory operator config block (kept consistent for launcher reads). */
  config: { joinedSolverNets?: Record<string, JoinedSolverNetConfig> };
}

export type JoinApplier = (entry: JoinedSolverNetConfig) => Promise<void>;

export function createJoinApplier(deps: JoinApplierDeps): JoinApplier {
  return async (entry: JoinedSolverNetConfig): Promise<void> => {
    const cid = entry.manifestCid;
    const roles = rolesFromJoinedConfig(entry);

    // (a) task-discovery cid set — solver role only (mirrors main.ts:1749-1751),
    // deduped so a re-apply does not double-push.
    if (entry.roles.includes('solver') && !deps.taskDiscovery.solverNetManifestCids.includes(cid)) {
      deps.taskDiscovery.solverNetManifestCids.push(cid);
    }

    // (b) engine eligibility view.
    deps.view.set(cid, { roles: entry.roles });

    // (c) readiness gate map — only when a solver harness is resolvable.
    // Evaluator-only joins use the contract-derived evaluator harness, which
    // the boot path also routes through the registry, not the readiness map.
    if (entry.roles.includes('solver')) {
      const harnessName = entry.harness ?? CLAUDE_CODE_HARNESS;
      await deps.readiness.setJoined(cid, { harnessName, roles: entry.roles });
    }

    // (d) SolverNet registry — shared boot/live registration (Task 1).
    await registerJoinedNet(deps.registry, cid, entry);

    // Keep the in-memory config consistent so launcher read-callbacks
    // (main.ts:1368) and any in-process re-read see the new entry. The
    // on-disk write is owned by the join endpoint.
    if (!deps.config.joinedSolverNets) deps.config.joinedSolverNets = {};
    deps.config.joinedSolverNets[cid] = entry;
  };
}
```

> `rolesFromJoinedConfig` is already exported from `registry.ts:69`. If `rolesFromJoinedConfig` is unused after the role-map (it is referenced above for the operator-role mapping the readiness/view want the raw `entry.roles` form), keep only what compiles — the view + readiness take the raw `'solver'|'evaluator'` roles (`entry.roles`), so the local `roles` binding may be dropped if `yarn typecheck` flags it as unused.
