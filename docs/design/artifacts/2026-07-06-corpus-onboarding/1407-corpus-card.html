Why "signal" went away

"Distribution Signal" describes what the indexer computes; "Corpus" names what the network owns. The spec (§2.4) models this card as the summary face of the Corpus surface — card = summary, tab = full — so the card should read as a description of the corpus a first-time viewer can parse without protocol context. The analytical framing ("signal", "concentrates") survives where it earns its place: the bars' eyebrow.

One gold on the Network surface

The corpus total in the summary sentence takes --gold-400 — the Network view currently has no gold hero, so the entry point to the network's public good is the right single emphasis. Everything else on the card stays sky/bone. (Tier chips don't appear here at all — volume, not verification.)

Where the seed distinction went

The old card's central complication — envelope-only vs include-seeded, with a stated excluded total — is retired from this surface. The backend keeps its envelope-only default (spec §3.2); the card simply reports those numbers without asking the viewer to understand a filter. An imported seed is a fact about one envelope's provenance, so it renders where that envelope renders: as a marker on the corpus-item detail (#1406). If an audit view of seeds is ever needed, it belongs behind ?include=raw on the tab, not on the Network summary.

Voice check

  • No "distinct contributors" phrasing in the headline — "23 operators" reads plainly; the per-cluster counts remain labelled Contributors since they overlap and don't sum.
  • Empty copy matches the tab verbatim, so the two surfaces never disagree about what "empty" means.

Open questions

  • Cluster row link target. Cluster names link to the Corpus tab; ideally pre-filtered (/corpus?cluster=jinn-agent). Needs the index filter param from #1406's open list.
  • Card length. The breakdown table caps at the low-volume fold. If cluster count grows past ~10, the card should truncate to top 6 + "and N more →" rather than grow — flagged for the explorer owner.
